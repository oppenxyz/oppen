# Oppen app UI review — 7 September 2026

Proposal for evaluation, not an implementation decision.

The website is live with Terrain v2, inspection lighting, stronger ASCII contrast, corrected candle forms and framed wordmark corners. The app already shares its typography, dark housings and sampled geometry. Its biggest opportunity is to make that visual precision serve the operator: readable numbers, unmistakable state, and detailed instruments that carry real information.

## Review scope

Inspected the installed `/Applications/oppen.app` on testnet: Trade, Agents, Builder, Portfolio, Settings, Setup and the walkthrough entry. Public market data was available; no account was configured. Cross-checked Vue components, renderer, stores, design rules, spec and decisions. Source began at `5e214e7` and advanced independently to `28fbf36` during the review; desktop files did not change between those commits. The installed binary's commit was not established.

Funded accounts, active agents, approvals, trading, outages and mainnet switching were not exercised. Findings below distinguish visible defects, source-backed gaps and proposed design work. No runtime code, account settings or existing backend work was changed.

## Fix first

### 1. Keep the complete chart inside its housing

**Confirmed visually and in source.** The right price scale and last-price label are clipped in the current window. `CandleChart.vue:54` allocates candle slots using the entire host width, while `lib/candles.ts:495` adds a separator and a dynamically sized price gutter afterward. The host hides overflow.

Reserve the measured gutter before calculating slots, and remeasure when the font becomes ready. Preserve the deterministic OHLC renderer, its proper bodies/wicks, volume and price precision. Verify long price labels, low-priced assets, forming bars and resizing at the supported minimum window size. Trace: chart spec §2; decisions U1/U2.

### 2. Establish a display precision policy

**Confirmed visually.** Spread currently reads like `1.0117745260468704549191210000 bp`; imbalance and volatility have similarly long decimals. `vol_ratio` renders literally as `null`. This makes the feature panel harder to interpret and consumes space needed for labels.

Use field-specific display formatting: for example spread `1.01 bp`, volatility `1,393.68 bp`, funding `−0.86 bp`, and an explicit missing-value label. Give imbalance and volume ratio clear definitions and units. Preserve exact source values for detail inspection; display rounding must never become order input or replace exact wire values. Add Price, Size and Orders headings to the book, with the size unit visible. Keep the existing partial-depth “floor” qualifier and explain its coverage.

Evidence: `views/TradeView.vue:48–75`, book and feature templates. Trace: spec #31 and F; decision J1.

### 3. Separate unknown, empty, stale and unavailable

**Confirmed visually; freshness gap supported by source.** With no account configured, Portfolio says “No open positions,” reports zero positions and exposes a 0% margin gauge. Trade's ledger is a placeholder with hardcoded zero counts. These statements look like account facts. The footer carries the actual account error, but truncates it.

Before a successful account read, show “Account not connected” and a setup action; use zero only for a successful empty result. Retain last good data on failure, but mark its age where it is used. Market freshness exists in the store and footer, yet Trade does not apply the stale chart treatment required by the spec. Distinguish public market connectivity from account connectivity throughout Setup and the shell.

Evidence: `views/PortfolioView.vue:13,36,85,95,114`; `views/TradeView.vue:194–210`; `stores/shell.ts`; `components/shell/AppStatusBar.vue`. Trace: spec #4, #31, #34.

### 4. Make capability and control language accurate

**Confirmed in UI and source.** “Manual order — Overrides policy” suggests bypassing protection; the ticket is currently a placeholder. “LOCAL · RUNTIME OK” is hardcoded. Builder presents source choices and disabled controls without a usable authoring path. Settings navigation looks interactive but is static.

Label manual orders as operator initiated and subject to the shared execution checks. Derive operational status from authoritative reads. Clearly identify unfinished capabilities next to the control, rather than relying on a disabled button's tooltip. Make available settings sections actual navigation; present unavailable sections as planned. Use “container” instead of blanket “sub-account,” and clarify whose margin/equity a total represents. Mainnet switching needs the explicit persisted behavior required by D4 before being considered complete.

Evidence: `views/TradeView.vue:238`; `components/shell/AppHeader.vue:39,58`; `views/BuilderView.vue`; `views/SettingsView.vue`; `views/PortfolioView.vue`; `stores/shell.ts`. Trace: D1/D4/D8, spec #26–33. These are frontend readiness gaps, not claims that the Rust safeguards are absent.

### 5. Repair compact-window and walkthrough behavior

**Confirmed visually.** Setup's bottom actions overlap walkthrough copy in the current window. Dense headings clip. The walkthrough's highlighted navigation remains dim: a full-screen scrim covers the supposed hole, with another dimming shadow outside it.

Let Setup content determine its scroll height and keep actions outside overlapping content. Check the supported 1280×720 minimum and default 1440×900 window, including long errors and larger text. Use one spotlight mask so its target remains readable. The dialog source also lacks focus entry, trapping and restoration; add these and ensure Enter advances only once. Position callouts using their actual height instead of the fixed 190px estimate.

Evidence: `views/OnboardingView.vue:92`; `components/tour/TourSpotlight.vue:57,100,139,170`. Trace: spec #4, #36; design system's readable hierarchy.

## ASCII and contrast proposal

**Terrain for arrival.** Reuse the website's nested terrain and pointer inspection on Setup. Keep it behind the brand side, with a solid black wordmark plate and corner markers. Its composition should remain complete with motion disabled. The task/checklist side should stay still and readable.

**Measured detail for operation.** Put complexity into book depth, utilization, exposure and freshness indicators. More cells should reveal magnitude, thresholds or coverage. Avoid decorative movement that could be mistaken for live feed activity. Hover can reveal a row's detail or strengthen a boundary without shifting the plotted data.

**Apertures with distinct states.** Replace the same large breathing mark in every empty panel with a smaller, crisp static aperture for empty states, a recognizable read-in-progress pattern only during actual reads, and explicit text for unavailable/error states. Keep the richer brand composition on Setup, where it has room and purpose.

**Contrast by role.** Make important values bright, working labels comfortably readable, and housing rules subdued. Reduce excessive tracking on dense labels and test larger working-data text before raising every gray token. Spend uranium on a selected or exceptional fact. Avoid covering every panel in equally bright brackets.

**Preserve deliberate chart semantics.** Decision U3 explicitly authorizes green/red candles alongside shape differences. Retain that decision; the website's monochrome marketing illustration does not override it. Update the older design README to acknowledge the exception. Distinguish the five-glyph artwork ramp from the chart's specified structural glyphs.

**Motion belongs to decoration.** The app already honors reduced motion in its 90ms decorative clock. Add an explicit decorative-motion setting and pause decorative sampling when hidden. Market reads, order state and freshness tracking must continue independently. The active candle component should expose a concise accessible chart summary rather than relying on a character wall.

## Suggested implementation order

1. **Legibility and truthful state:** chart gutter; display formatting/nulls; unknown account states; stale presentation; accurate manual/status copy; Setup overflow; walkthrough mask/focus. Review at minimum/default window sizes. Use targeted regression checks for geometry, formatting and state transitions.
2. **Operator workflows:** actionable empty states, working navigation, and data-backed Agents/Builder/ledger surfaces using existing read models. Acceptance depends on actual backend capabilities; visual polish must not simulate completion.
3. **Brand detail:** Setup terrain and framed wordmark, refined aperture states, quantitative ASCII gauges, consistent brackets and decorative-motion controls. Compare still frames and reduced-motion behavior alongside live interaction.

I recommend starting with the first pass, then evaluating the Setup terrain and one real book/gauge treatment together. That gives us a concrete test of the website's direction inside the app before expanding it across every screen.
